# Axes

An **axis** is a named continuum with two ends that a competent person can argue for. Three to five
axes bound the space. With fewer, the space is a point. With more, nobody can hold it in their head.

The axes that matter are specific to the project and use the product's own vocabulary. Derive them
first. If a derived list comes out thin, react against the examples below. Never pick from them as
a menu.

## Naming one

- **Extract it from a concept.** The user describes a design in concrete terms: the incumbent
  screen they hate, a product they love, or a corner already on the table. Put that concept at one
  end and its honest opposite at the other. The axis is grounded and already in their words.
- **Invert an anti-reference.** Do the same move on what was rejected. Three anti-references
  usually yield one real axis between them.
- **Take the noun of the thesis and find its opposite.** If the thesis claims "a workshop, not a
  gallery", then workshop <-> gallery is an axis, in the user's language.
- **Find the argument.** If the user contradicts themselves across the session, that is a live
  axis, not a mistake. Name it and hand it back.
- **Ask what the medium could be.** Print, terminal, instrument panel, board game, ledger, map,
  darkroom. The position of the thing between two media is often the sharpest axis available.

## Axes that recur

These are prompts, not a checklist. They have two uses: a starting shape when a derived axis is
still fuzzy, and a check that a named axis is a real decision. Rename the ends into the product's
language before any of them reaches the page. A borrowed end says nothing about this product. If
nobody recognises an axis as theirs, it does not survive the first argument about it.

**What it is.** tool <-> environment (picked up for one job, or inhabited); instrument <->
appliance (rewards practice, or works identically forever); document <-> application (read, or
operated); single surface <-> system (one screen, or a world with rooms).

**How it behaves.** ceremony <-> immediacy (confirms and steps, or one irreversible-feeling
action); guided <-> open (the path is laid, or the user assembles it); foreground <-> ambient
(demands attention, or lives at the edge); progressive <-> flat (depth as competence grows, or
everything at once).

**How it feels.** formal <-> familiar (where the copy and the chrome sit; drives voice as much as
type); authority <-> companionship (it knows and tells you, or works alongside you); confident
<-> careful (acts and offers undo, or asks first); restraint <-> exuberance (how much the surface
can perform). Quiet is not the same as restrained. A quiet design can be very expressive, and a
loud one can be disciplined.

**How it is made.** dense <-> airy (the axis most often decided by accident); structural <->
decorated (beauty from the arrangement, or applied); native <-> bespoke (platform conventions, or
its own vocabulary); uniform <-> composed (one kit everywhere, or each screen art-directed).

**Who it is for.** novice-first <-> expert-first (the first hour, or the thousandth); solo <->
social (whether other people are visible); consumer <-> practitioner (whether using it is part of
someone's job).

## The test

1. **Both ends are defensible.** If one end is "cluttered" and the other is "clean", it is a
   preference in a costume, not an axis. Rename the ends until a competent designer can pick
   either: "dense" <-> "airy".
2. **The category has a default position on it.** Name it. If you cannot say where everyone else
   sits, the axis does not describe a real decision in this category.
3. **A move along it changes the build.** If an axis produces the same components at either end,
   it is decoration. Density changes the grid. Register changes the copy *and* the type. Ceremony
   changes the step count of the flow.
4. **It is not already settled.** If the user has locked an axis (platform, brand color, an
   accessibility floor), it belongs in **Fixed**, not in the space.

## Putting a position to the user

Ask about one axis per question round. Give the two ends, and give the category default as its own
option so the user sees what they refuse. The answer is a coordinate. Record where they sit *and
why*. A build skill reads the why when a detail is under-specified.
