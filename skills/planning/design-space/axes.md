# Axes

An **axis** is a named continuum with two ends someone could reasonably argue for. Three to five of
them bound the space. Fewer and the space is a point; more and nobody can hold it in their head.

There is no library of axes here on purpose. A list of pre-named dimensions becomes the answer, and
the resulting space is the generic one every category already has. The axes that matter are
project-specific and arrive in the product's own vocabulary.

## Naming one

- **Extract it from a concept.** Someone has described a design in the concrete — the incumbent
  screen they hate, a product they love, a corner already on the table. Name what that concept is
  at one end and the honest opposite at the other. Grounded, and already in their words.
- **Invert an anti-reference.** Same move, aimed at what was rejected. Three anti-references usually
  yield one real axis between them.
- **Take the thesis's noun and find its opposite.** If the thesis claims "a workshop, not a
  gallery", then workshop <-> gallery is an axis, in the user's language.
- **Find the argument.** Whatever the user has contradicted themselves on across the session is a
  live axis, not a mistake. Name it and hand it back.
- **Ask what the medium could be.** Print, terminal, instrument panel, board game, ledger, map,
  darkroom. Where the thing sits between two media is often the sharpest axis available.

## The test

1. **Both ends are defensible.** If one end is "cluttered" and the other is "clean", it is not an
   axis, it is a preference wearing a costume. Rename the ends until a competent designer would
   pick either: "dense" <-> "airy".
2. **The category has a default position on it.** Name it. If you cannot say where everyone else
   sits, the axis is not describing a real decision in this category.
3. **Moving along it changes the build.** An axis that produces the same components either way is
   decoration. Density changes the grid; register changes the copy *and* the type; ceremony changes
   the flow's step count.
4. **It is not already settled.** An axis the user has locked (platform, brand color, an
   accessibility floor) belongs in **Fixed**, not in the space.

## Putting a position to the user

One axis per question round: the two ends, plus the category default as its own option so the user
can see what they are refusing. What comes back is a coordinate — record where they sit *and why*,
since the why is what a build skill reads when a detail is under-specified.
