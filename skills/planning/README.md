# Project Planning

Skills for turning ideas into a bounded design space, then into executable, well-formed backlogs.

| Skill | What it does |
| --- | --- |
| [`design-space`](./design-space/SKILL.md) | User-invoked (`/design-space`). A charrette that runs before any code, comp, or prototype: grounds in what exists, lands a thesis and three named anti-references, names the axes the design actually varies on, generates 4–6 mutually incompatible corners, and marks what's live, dead, and open. Output is a one-page written space a build skill executes against. |
| [`linear-method`](./linear-method/SKILL.md) | The [Linear Method](https://linear.app/method) as working rules: initiatives and backwards-derived goals, enabler-vs-blocker prioritization, projects scoped to 1–3 weeks with 1–3 people, issues instead of user stories, n-week cycles mixing feature and quality work, staged design projects, and launch-and-keep-launching. Splits by branch — `direction.md` for shaping what to build, `building.md` for doing it. |
| [`plan-project`](./plan-project/SKILL.md) | User-invoked (`/plan-project`). Takes a project from "I have ideas" — plus any design docs or ADRs — to a review-ready backlog: reconciled intake, vertical-slice breakdown, mini-PRD tickets, dependency-aware sequencing, capacity-aware assignment, and shaping for Jira or Linear. Codebase-aware; produces markdown, never live writes. |
